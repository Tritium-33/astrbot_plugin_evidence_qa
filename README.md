# 证据问答与会话路由

[更新日志](CHANGELOG.md)

适用于 AstrBot 4.29.3 的私聊（含 WebChat）。闲聊沿用当前模型与人设；资料问题交给研究模型，按内容选择联网或原生知识库。运行数据保存到 AstrBot 的插件数据目录，源码中不放测试、审计或构建文件。

## v0.2.1 的流程

```text
用户消息 → 一次任务规划
  ├─ 日常聊天 → 当前模型 → 短回复
  ├─ 资料查询 → 原生联网 / 匹配的本地库 / 两者
  │             → 一次结构化生成 → 引文校验与语义核验 → 仅答案
  ├─ 追问来源 → 同会话已保存的证据 → 原文与出处
  └─ 图片等其他任务 → 交还原生 Agent
```

资料答案内部保留逐项结论与来源。本地文献要求逐字引文；联网内容允许像搜索助手一样引用已取得的来源 ID，无须为概述硬抄原句。审查模型核对结论是否由实际材料支持，包括型号、改型后缀、阶段、条件、数量、单位和新闻日期。允许引用连续段落中的代称，不要求每个片段重复型号。历史回答和用户纠正不作为独立文献证据。

正常路径只有规划、原生生成、语义审查三次模型调用。材料不足时，回答模型可提出新的搜索词或具体网址，插件执行后继续回答；最多两轮后续生成，其中无新检索的修正最多一次。初查最多四次、补查总计最多两次，主动阅读指定网址也占补查预算。所有调用仍受整轮超时约束。

按条目校验，一条引文失败不会连带丢弃其他条目。本地引文仅允许还原原文中的空白差异，不改字词、数字或单位。网页引文不匹配时移除该引文，保留真实来源交给语义审查，不把错误引文展示给用户。后续调用失败时保留已通过审查的部分；新证据推翻原结论时以新的审查结果为准。

无可靠答案、模型或搜索失败时，用户侧静默结束，原因写日志/trace；不会发送失败模板、未经核验的草稿或无关原文。日志不是成功保证，分类与语义核验仍可能受模型判断影响。

## 模型与搜索配置

1. 在 AstrBot 配置默认聊天模型，例如 Gemini；保留你需要的原生回退模型。插件不改全局模型或原生额度回退配置。
2. 插件配置 `worker_provider_id` 填 **Provider ID**（例如你的 DeepSeek 提供商 ID），负责规划、审查与目录概括。
3. `research_provider_id` 填资料回答模型的 Provider ID，通常也选 DeepSeek。留空沿用当前模型。用户本轮显式选模型时优先保留其选择。
4. 在 AstrBot 打开原生 `web_search`，选择搜索服务并配置搜索密钥。聊天模型的 Key 不等于搜索服务已启用。
5. 保留 AstrBot 原生知识库选择、Embedding 和 Rerank 配置。插件调用原生 `kb_manager.retrieve`，没有另建向量库或另做重排序。

联网默认使用 AstrBot 当前配置的搜索工具，支持 DeepSeek、Tavily、Bocha、Brave、Firecrawl、Baidu AI Search、Exa、AnySearch、SerpAPI。DeepSeek 和 Tavily 每次最多取 8 条搜索结果。页面按可读性及不同站点安排读取顺序，同一路径的跟踪参数和语言参数变体合并，实际文章 ID 参数保留。

DeepSeek、Tavily、Firecrawl、Exa 每次搜索尝试读取至多 4 个不同页面，目标取得 2 个正文，读取失败会递补其他结果；保留搜索摘要供回答。也可按模型的后续请求直接读取具体 URL。其他服务保留搜索摘要并明确其性质，不假称已经读过网页全文。网页失败记录脱敏后的异常详情，不把无关本地资料当作替代品。

“最新动态”“越野越好”等请求分别保留时效和广泛搜罗的意图；正式发布、媒体报道与社区传闻在回答中区分。模型按结果决定是否补查，不要求用户手动给搜索指令。这里使用 AstrBot 的原生搜索和阅读工具，不包含 Codex 的搜索服务，也不保证不同搜索供应商能返回相同结果。

新闻、近期动态等通常联网；主题匹配本地目录时才查本地。明确“只查本地/不要联网”时尊重要求，即使尚无目录缓存也可查询当前已选库。目录描述是范围提示，不是型号白名单。

## 资料目录：手动刷新

管理员在机器人私聊中发送：

```text
/资料目录更新
```

初次使用及上传、删除、更换文档后执行一次即可。不需要自己总结书籍或添加条目。

- 启动只加载 `catalogue.json`，不扫描正文、不调用模型，没有定时刷新任务。
- 手动更新时只读扫描原生文档，计算内容指纹，使用标题和分布抽样自动概括范围。仅新增/变化的文档调用概括模型；删除文档会从缓存移除。
- 目录不是全文索引。改型/参数的确证仍来自实际检索，摘要不能证明某主题在书中不存在。
- 失败保留上次完整缓存。刷新不会重新嵌入或改变原始知识库。
- 提问时从内存读取已选库的概览，放进原有规划请求；没有额外的“读取目录”模型调用。增加的输入量随文档概览数增长。

目录刷新命令需要 AstrBot 管理员权限。配置管理员后使用；命令结束会报告文档数和重新概括数。

## 回复长度与来源

日常回复通常 1–3 句，目标约 15–60 字，最多 80 字；强调完整自然句子，避免舞台动作、标题和长篇安慰。超长时最多压缩一次，不用截字符串制造残句。明确要求长文、小说或详细说明的任务豁免。

资料回答默认只给结论；原文、文档位置或网页 URL 保存在内部证据快照。来源追问显示对应文献引文或网页链接；保存了逐字网页摘录时也会显示该摘录。随后可以问：

- “刚才这个结论的原文和出处是什么？”
- “前面 906B 携弹量那条的来源呢？”
- “只给第二项的出处。”

来源取自对应回答当时的证据，不重新搜索拼出新出处；按平台会话及 AstrBot conversation ID 隔离。换新会话不继承旧会话证据。目前保留最近 20 条资料记录，规划展示本会话所保留记录的问题，最近 4 条额外提供逐项结论供定位。无对应证据时不冒用其他轮次的来源。

若人设写了“每次必须列出出处/长篇分析”，建议去掉该固定输出格式，保留事实准确和自然聊天要求；插件也会附加本轮格式规则。

## 与型号兼容插件、LivingMemory 一起用

- 型号兼容插件仍处理本地检索的别名、改型约束和邻接片段。这里不修改型号词典或语料。
- Rerank 使用 AstrBot 原生设置；未配置 Rerank 不会凭空生成重排。
- LivingMemory **2.8.1 / 2.8.2** 的私聊入口可被本插件跳过。默认资料轮、来源轮不进入记忆召回/记录；日常轮正常。
- “这轮别记”与混合提问可以请求跳过本轮记录。只有实际观察到召回及记录入口均被跳过，日志才记 `memory_isolated=true`。
- 不删除已有长期记忆，不清空聊天历史，不承诺撤销之前已写入的错误记忆。

建议分开测试：先闲聊，再问本地型号参数，再问最近 Gemini 新闻，随后分别追问两条来源。清洁会话可排除旧错误回答干扰；测试时核对 trace 的 `plan.source`、`operations[].channel`、`sources`、`items` 和 `timings`，不要仅凭回复自称“查询了知识库”判断。

## 超时与运行记录

| 设置 | 默认值 | 范围 |
|---|---:|---|
| `model_timeout_seconds` | 90 秒 | 每次规划、审查、补查后生成、修正或压缩 |
| `retrieval_timeout_seconds` | 45 秒 | 每次本地检索或联网搜索及其正文读取 |
| `page_timeout_seconds` | 15 秒 | 单个网页读取 |
| `turn_timeout_seconds` | 240 秒 | 从规划开始到答案核验结束，不含排队/发送 |
| `save_traces` | 开启 | 最近 20 份资料轮诊断记录 |

文件位于 `data/plugin_data/astrbot_plugin_evidence_qa/`：

- `catalogue.json`：手动刷新的资料范围。
- `evidence.json`：来源追问所需的最近 20 条证据快照，即使关闭诊断 traces 也保留。
- `traces/`：开启时保存本轮来源、答案、路由、调用耗时与记忆隔离状态；`validation` 记录各次候选输出（最多 16000 字符，标记是否截断）、逐项校验问题与审查结果。网页读取错误含脱敏后的具体原因。包含私人提问与原文，请按私人数据管理。

## 兼容范围与验证边界

依赖 AstrBot 4.29.3 的 `_select_provider`、`_apply_kb` 和普通 `run_agent` 内部接口，加载日志会报告接管三个入口。支持普通私聊和 WebChat；群聊、Live 不接管。LivingMemory 声明 2.8.1、2.8.2 适配。升级 AstrBot 后需要重新核验，不将私有内部接口视作稳定公开 API。

开发测试使用隔离的 AstrBot 原生代码、真实文献片段回放和明确的模型/搜索夹具。它能验证工具确实被调用、输出与历史一致、来源隔离及失败处理，不能证明任意模型总能正确分类、理解语义或读取网站。未安装到运行中的 AstrBot，也未以真实付费 API 做质量验收。
