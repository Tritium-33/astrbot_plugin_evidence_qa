# 证据问答与会话路由

[模型分工与配置](MODELS.md) · [群聊与图片配置](GROUP_CHAT_PLUS.md) · [更新日志](CHANGELOG.md)

适用于 AstrBot 4.29.3 的私聊、群聊与 WebChat。按消息选择自然聊天、本地原生知识库或联网查询。GPT 生成面向用户的主回答，DeepSeek 处理规划与辅助任务；默认简短聊天、按需给来源。源码只包含插件功能与使用文档。

## v0.5.3 的流程

```text
原生唤醒 / GCP 决定接话 → DeepSeek 规划
  ├─ 日常聊天 → 回答模型 → 直接回复
  ├─ 联网查询 → DeepSeek Search / Fetch → 回答模型 → 直接回复
  ├─ 本地查询 → 匹配的原生知识库 → 回答模型
  │             ├─ GPT 分工 → 直接回复（包括技术问题）
  │             └─ 原分工的本地技术问题 → 一次 DeepSeek 核验 → 回复
  ├─ 目录 / 来源追问 → 本会话缓存
  └─ 其他插件与工具委托 → DeepSeek / 原生工具
```

GPT 分工：白名单私聊及 WebChat 使用 Astra，群聊 RP 使用 Terra，群聊资料分析使用 Sol。三者分别选择 OpenAI 官方 `reasoning.effort`，默认 `low / low / medium`。图片直接交给回答模型；辅助路由只看文字、上下文和附件元信息。额度错误或手动切换后，回答恢复 Gemini / DeepSeek 原分工；辅助模型始终为 DeepSeek。

GPT 回答不运行后置审查或重写。原分工只对本地技术查询保留一次聚焦核验：检查型号、后缀、阶段、条件、数量、单位与文段归属；允许连续段落使用代称，不要求每段重复型号。历史回答和用户纠正不作为独立文献证据。

正常闲聊、联网和 GPT 本地查询只需“规划 + 回答”；原分工本地技术查询再加一次核验。初次检索并行执行，最多四次；回答模型可通过本轮工具 `evidence_lookup` 补查或读取网址，最多两次。工具交互会增加调用与耗时，材料足够时直接结束。

直接回答使用自然语言，不要求 JSON；内部来源标记发送前移除。来源追问读取当时的文段或网页信息。模型未建立逐句对应时明确说明。无结果或流程失败保持静默，原因写入日志与 trace，不发失败模板或无关原文。

各线路沿用同一会话的历史和人设，包括 GCP 提供的群历史，不为模型另建会话。来源按平台会话及原生 conversation ID 隔离。仅从持久历史移除本插件临时检索材料及工具过程，保留最终回复。

## 配置入口

完整填写表、官方思考选项、辅助模型设置及额度说明见 **[模型分工与配置](MODELS.md)**。升级后先填写新增的 GPT Provider ID 与私聊白名单；不要把 API 模型名称当成 Provider ID。GPT 提供商使用 OpenAI Responses。

- 原生默认模型与独立辅助插件配置为 DeepSeek；受管回答由本插件选择 GPT。
- 原生联网搜索启用 DeepSeek Search / Fetch，并填写搜索服务密钥。
- 保留原生知识库、Embedding、Rerank，不需要重建索引。
- `/模型检查` 查看 ID、模型、思考档位与 GCP 接管入口，不调用 API。
- 在插件配置的“回答模式”选择 GPT优先 或 Gemini/DeepSeek，保存即可切换；状态跨重启保留。聊天命令仍为可选快捷方式。

`模型分工` 关闭时保留 v0.4 的 worker/research/vision 配置行为，也不再执行新的私聊白名单规则。启用时私聊白名单为空不会开放 QQ 私聊；WebChat 单独允许。通常群聊只接管已经触发的回复，沿用 GCP 的概率、冷却或密度设置。

需要取消群聊冷却限制，在本插件配置的 **「免冷却群」** 中填写群号，一行一个。这些群继续经过 GCP 原有概率筛选和 DeepSeek「是否接话」判断，只取消回复密度限流、对话疲劳及注意力冷却；不会每条必回，也不会强制唤醒。群聊 RP 仍用 Terra，资料分析仍用 Sol，辅助仍用 DeepSeek。移除群号即可恢复原有冷却限制。详见 [免冷却群配置](GROUP_CHAT_PLUS.md#免冷却群保留读空气判断)。

## 图片与群聊

支持纯图片、图文、引用图片、带 URL 的 NapCat `mface`；GIF 沿用原生抽帧。只有表情编号时不会冒充看到画面。尊重 GCP 选定的图片范围与数量，引用图片保留引用文字；图像编辑委托保留原图。

GCP 普通接话判断与独立主动发言已分别适配：辅助判断用 DeepSeek，最终回答按私聊／群聊分工走 GPT。读空气只看文字与附件数量，不消耗 GPT 识图调用，也不把图片交给纯文本辅助 API。该判断不能根据梗图视觉内容决定是否插话；决定回应后，GPT 才读取原图。具体频率和图片设置见 [群聊配置](GROUP_CHAT_PLUS.md)。

## 联网与本地检索

联网默认使用 AstrBot 当前配置的搜索工具，支持 DeepSeek、Tavily、Bocha、Brave、Firecrawl、Baidu AI Search、Exa、AnySearch、SerpAPI。DeepSeek 和 Tavily 每次最多取 8 条搜索结果。页面按可读性及不同站点安排读取顺序，同一路径的跟踪参数和语言参数变体合并，实际文章 ID 参数保留。

DeepSeek、Tavily、Firecrawl、Exa 每次搜索尝试读取至多 4 个不同页面，目标取得 2 个正文，读取失败会递补其他结果；保留搜索摘要供回答。也可按模型的后续请求直接读取具体 URL。其他服务保留搜索摘要并明确其性质，不假称已经读过网页全文。网页失败记录脱敏后的异常详情，不把无关本地资料当作替代品。

“最新动态”“越野越好”等请求分别保留时效和广泛搜罗的意图；正式发布、媒体报道与社区传闻在回答中区分。模型按结果决定是否补查，不要求用户手动给搜索指令。这里使用 AstrBot 的原生搜索和阅读工具，不包含 Codex 的搜索服务，也不保证不同搜索供应商能返回相同结果。

新闻、近期动态等通常联网；主题匹配本地目录时才查本地。明确“只查本地/不要联网”时尊重要求，即使尚无目录缓存也可查询当前已选库。目录描述是范围提示，不是型号白名单。

## 资料目录：手动刷新

管理员在机器人私聊中发送：

```text
/资料目录更新
```

初次使用及上传、删除、更换文档后执行一次即可。不需要自己总结书籍或添加条目。

- 启动只加载 `catalogue.json`，不扫描正文、不调用模型，没有定时刷新任务。
- 手动更新时只读扫描原生文档，计算内容指纹，使用标题和分布抽样自动概括范围。仅新增/变化的文档调用概括模型；删除文档会从缓存移除。
- 目录不是全文索引。改型/参数的确证仍来自实际检索，摘要不能证明某主题在书中不存在。
- 失败保留上次完整缓存。刷新不会重新嵌入或改变原始知识库。
- 提问时从内存读取已选库的概览，放进原有规划请求；没有额外的“读取目录”模型调用。增加的输入量随文档概览数增长。

目录刷新命令需要 AstrBot 管理员权限。配置管理员后使用；命令结束会报告文档数和重新概括数。

## 回复长度与来源

日常回复在生成前提示通常 1–3 句、约 15–60 字、尽量不超过 80 字，强调完整自然句子。首次回复直接发送，不另调模型压缩，也不截断字符串；字数是表达指导，不是程序硬上限。明确要求长文、小说或详细说明的任务豁免。

资料回答默认只给结论；原文、文档位置或网页 URL 保存在内部证据快照。来源追问显示对应文献引文或网页链接。原分工的本地技术核验保留逐字引文；GPT 等直接回答保存模型标注的段落与来源关联，不等于额外核验过支持关系。若模型未标注来源，则明确列出“本轮检索到的来源（未建立逐句对应）”，不会伪造逐句引文。随后可以问：

- “刚才这个结论的原文和出处是什么？”
- “前面 906B 携弹量那条的来源呢？”
- “只给第二项的出处。”

来源取自对应回答当时的证据，不重新搜索拼出新出处；按平台会话及 AstrBot conversation ID 隔离。换新会话不继承旧会话证据。目前保留最近 20 条资料记录，规划展示本会话所保留记录的问题，最近 4 条额外提供逐项结论供定位。无对应证据时不冒用其他轮次的来源。

若人设写了“每次必须列出出处/长篇分析”，建议去掉该固定输出格式，保留事实准确和自然聊天要求；插件也会附加本轮格式规则。

## 与型号兼容插件、LivingMemory 一起用

- 型号兼容插件仍处理本地检索的别名、改型约束和邻接片段。这里不修改型号词典或语料。
- Rerank 使用 AstrBot 原生设置；未配置 Rerank 不会凭空生成重排。
- LivingMemory **2.8.1 / 2.8.2** 的私聊入口可被本插件跳过。默认资料轮、来源轮不进入记忆召回/记录；日常轮正常。
- “这轮别记”与混合提问可以请求跳过本轮记录。只有实际观察到召回及记录入口均被跳过，日志才记 `memory_isolated=true`。
- 不删除已有长期记忆，不清空聊天历史，不承诺撤销之前已写入的错误记忆。

建议分开测试：先闲聊，再问本地型号参数，再问最近 Gemini 新闻，随后分别追问两条来源。清洁会话可排除旧错误回答干扰；测试时核对 trace 的 `plan.source`、`operations[].channel`、`sources`、`items` 和 `timings`，不要仅凭回复自称“查询了知识库”判断。

## 超时与运行记录

| 设置 | 默认值 | 范围 |
|---|---:|---|
| `model_timeout_seconds` | 90 秒 | 每次规划、本地技术核验或手动目录概括 |
| `retrieval_timeout_seconds` | 45 秒 | 每次本地检索或联网搜索及其正文读取 |
| `page_timeout_seconds` | 15 秒 | 单个网页读取 |
| `turn_timeout_seconds` | 240 秒 | 从规划开始到答案核验结束，不含排队/发送 |
| `save_traces` | 开启 | 最近 20 份资料轮诊断记录 |

原生回答及工具交互还受 AstrBot 提供商自身超时与本插件整轮预算约束。取消多次审查减少的是串行调用，实际速度仍取决于模型、搜索及网页读取，不能保证固定秒数。

文件位于 `data/plugin_data/astrbot_plugin_evidence_qa/`：

- `catalogue.json`：手动刷新的资料范围。
- `evidence.json`：来源追问所需的最近 20 条证据快照，即使关闭诊断 traces 也保留。
- `routing.json`：当前回答分工与切换原因。
- `traces/`：开启时保存本轮来源、答案、路由、调用耗时与记忆隔离状态；`answer_mode` 区分 `direct` 与 `local_technical`。只有原分工的本地技术核验会产生非空 `validation`，记录草稿（最多 16000 字符，标记是否截断）、逐项问题及一次审查结果。网页读取错误含脱敏详情。包含私人提问与原文，请按私人数据管理。

## 兼容范围与验证边界

QQ 图片恢复适配 AstrBot 4.29.3 的图片预处理入口及 OneBot `get_image`。CDN 下载失败时优先读取 NapCat 返回的本地原图，再交给 Chat Plus 和回答模型。配置及验证方法见[模型配置](MODELS.md)。

依赖 AstrBot 4.29.3 的选模、请求收集、知识库、压缩、WebChat 标题与普通运行器内部接口；加载日志报告实际接管入口数量。支持私聊、群聊与 WebChat，不接管 Live。Group Chat Plus 衔接按 V1.2.3.hotfix.2 的请求、接话判断与主动生成接口验证；LivingMemory 2.8.1、2.8.2 隔离适配范围为私聊。群消息采集、Group Chat Plus 自行召回及独立记忆写入不在此隔离保证内，不能把“这轮别记”理解为所有群聊记忆路径均被阻断。升级后需要重新核验这些内部接口。

开发测试使用隔离的 AstrBot 原生代码、真实文献片段回放和明确的模型/搜索夹具。它能验证工具调用、输出与历史一致、来源隔离及失败处理；图片回放检查 Responses 的 `input_image` 包含可解码的像素。离线测试不代表真实模型质量验收，部署后仍需核对实际请求与回复。
