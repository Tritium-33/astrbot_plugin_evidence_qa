# 文献证据问答

为 AstrBot 私聊增加完整的资料问答流程：补全追问、分对象与属性检索原生知识库、复核回答并附可核对的原句。沿用原生 Embedding/Rerank，可与型号写法兼容插件共用。

## 配置

1. 在 AstrBot 后台的插件页打开“安装插件”，上传 `astrbot_plugin_evidence_qa-v0.1.1.zip`。
2. 打开“文献证据问答”的配置，把已创建的 DeepSeek 文本模型 **Provider ID** 填入下面两个模型字段；不是 API Key，也不是模型名称。
3. 在 AstrBot 原生知识库中保留当前库、Embedding 和 Rerank 配置，并让当前会话选中需要的库。现有型号兼容插件可以继续启用。
4. 保留原日常聊天模型和人格设置。插件加载后，直接在同一个 QQ 私聊提问，无须附加命令前缀。

安装 ZIP 后，在插件配置中填写已配置的 Provider ID。`worker_provider_id` 用于任务规划与语义审查；`research_provider_id` 用于技术问答的草稿及最终文献答案整理，可设为 DeepSeek。日常聊天继续使用 AstrBot 当前模型，例如 Gemini。均留空时使用当前模型。

人格、QQ会话和 AstrBot 聊天历史不迁移。此版接管原生 Agent 的普通私聊，包含 QQ 和 WebChat 网页单聊；闲聊也会增加一次规划调用。Live 语音模式完全交回原生流程，不适用本插件的复核与记忆隔离。普通私聊在实际模型执行前关闭流式，技术回复经复核后才进入发送流程。

需要使用原生知识库；普通模式和 Agentic 模式均会由本插件主动做分项检索，无须“请先查询知识库”前缀。普通模式原有检索仍会执行一次，闲聊也可能走这次原生检索；没有插件 research trace 不代表完全没有检索。

本插件接管的技术轮次使用本地文献流程，关闭该轮自由工具调用，防止未经复核的工具中间答复提前发出。明确联网或图片请求由规划器交回原生流程，不由此插件核验。

## 流程

1. 用最近六条对话补全指代，判定闲聊、资料查询或记忆控制。
2. 首轮最多四次原生检索，缺项时最多补查两次：插件最多六次，普通模式另可能有一次原生检索。合并完整片段、保留邻段；同一来源返回不同文本时均保留，并标明本次返回版本。当前会话的知识库选择优先于全局设置。
3. 回答模型生成草稿，复核模型结合实际原文重整答案；另一次审查检查结论支持关系、漏项和虚构过程。缺项最多补查两个查询，再复核一次。
4. 程序检查每条引文确实逐字存在于对应片段，模型审查通过后输出结论、来源和原句。复核不可用时展示实际片段，不把未经复核的草稿当作最终答案。
5. 规划超时或格式错误会重试一次，仍失败时明确报告流程不可用并隔离该轮记忆；不会静默发送未经核验的技术草稿。规划在原生会话锁内、选择回答模型前执行，避免排队追问使用过时历史或选错模型。

插件仅声明支持 **AstrBot 4.29.3**，安装兼容范围锁定为这个版本。它对模型选择、原生知识库阶段和普通 Agent 输出入口进行可逆运行时包装，卸载时撤销；不改核心文件。启动日志列出三个接管入口，最终日志记录实际非流式执行、回答替换和历史同步。已有显式单轮模型选择优先于自动路由。其他版本须重新验证，第三方 Agent 运行器不在适配范围。

每次资料查询通常额外使用一次规划、一次答案整理和一次语义审查调用；补查时再增加整理/审查调用。闲聊增加一次规划调用。费用按所选模型的实际API计费。程序校验能证明引文存在，语义支持与完整性仍由模型审查判断；将两个 ID 设为同一模型时，审查与整理也来自同一模型，不是独立模型验证或形式化证明。

显式单轮模型选择也决定最终答案整理使用的模型，审查仍由 worker 执行。本插件不实现 Gemini 日额度检测；规划、整理和审查直接调用指定提供商，不继承原生草稿的故障回退。因此建议把 worker 和 research 均设为可用的 DeepSeek，Gemini 只承担日常聊天。

## 耗时配置

| 字段 | 默认值 | 作用 |
| --- | ---: | --- |
| `model_timeout_seconds` | 90 秒 | 每次规划、答案整理及语义审查调用 |
| `retrieval_timeout_seconds` | 45 秒 | 单次完整检索阶段，含选库、嵌入、搜索和原生 Rerank；普通模式原有知识库阶段也受此限制 |
| `turn_timeout_seconds` | 240 秒 | 从会话锁内开始规划累计计时，限制后续知识库、原生草稿生成和插件复核的剩余时间 |

三个字段均可配置为大于零的秒数。单次调用实际可用时间不超过整轮剩余预算。整轮预算不计排队、QQ发送和最终历史写入时间，也不强制终止其他插件自行启动的后台任务。超时会停止后续调用，已有文献片段仍可作为原文摘录返回；原生草稿超时也会生成可保存的最终回复，不把半成品草稿发出。取消依赖异步服务正常响应取消信号，不能中断阻塞事件循环的同步代码。

保留六次检索上限；只有时间预算不足才减少实际完成次数。可按实际 API 延迟调整，不必固定为20秒。

## 长期记忆

适配 LivingMemory 2.8.1 私聊事件入口，运行时可逆包装，不修改其文件或数据库。被本插件判定为技术问答的轮次默认跳过其召回与消息记录；日常聊天照常进入 LivingMemory。普通 AstrBot 历史保留，包括先前的对话，不能将“不召回长期记忆”理解为清空历史。

已存在的记忆和已进入总结缓冲区的旧消息不会删除。其它插件的主动写入、其它版本或群聊被动采集不在该适配范围内。自然语言“不记住”不能追溯撤回旧记录。

单纯的“不保存本轮”请求关闭该轮自由工具调用，并只报告已建立的记忆隔离状态；不会执行删除旧记忆。

## 核查

`save_traces` 默认开启，运行时在 `data/plugin_data/astrbot_plugin_evidence_qa/traces` 保留最近20次的查询、原文、来源和最终回答；会包含私人资料，可关闭。测试及开发记录不放在插件中。

首次使用可先问一句日常话，再问一个文献参数问题，随后用“它的弹药种类与数量呢？”追问。资料回答应带实际原句及来源；在记录中可看到补全后的问题、实际查询、完整片段、整理模型和审查模型的 ID。记录中的 `model_audited` 表示通过模型审查，不表示获得人工核验。

记忆状态分别记录：`memory_adapter_available` 是适配器可用，`memory_skip_requested` 是本轮要求跳过；`memory_recall_skipped` 与 `memory_record_skipped` 才是两个入口的实际观察结果。`true` 表示观察到跳过，`false` 表示观察到放行，`null` 表示未观察到该入口；只有两个入口都确实跳过，`memory_isolated` 才为真。不要只看“记忆库暂时没有新增行”，还应检查 LivingMemory 的消息采集与后续总结输入。

记录在最终回复与当前轮历史同步后保存，包含 `streaming`、`response_replaced`、`history_synced`、耗时和超时配置。验收时同时比对实际收到的文字与保存的历史，确认没有先发草稿再改答案。
